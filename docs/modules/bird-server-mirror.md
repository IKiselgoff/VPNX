# Module: bird-server-mirror

## Назначение
Поддерживать список кандидатов локального Telegram SOCKS-прокси из уже сохранённого BIRD-зеркала на VPS.

## Ответственность
Читает только локальный snapshot, валидирует и атомарно обновляет VLESS-кандидатов. Никогда не обращается к Happ-подписке. Не перезапускает работающий Xray при здоровом SOCKS; после двух неуспешных проверок вызывает штатный selector.

## Архитектурная роль
Серверный источник данных для VPNX mirror и `TeplonTelegramProxy.service`.

## Зависимости
Python 3, `curl`, `/var/lib/vpnx-bird/snapshot.json`, systemd timer, существующий Xray selector Telegram.

## Структуры данных
Список BIRD Xray-конфигов в зеркале и производный список VLESS URI; старые Telegram-кандидаты остаются fallback.

## Логика работы
Snapshot должен содержать 5–100 полных профилей и хотя бы один пригодный VLESS outbound. Новые узлы идут первыми, старые сохраняются. Замена списка кандидатов атомарна; при ошибке чтения или валидации он не меняется.

## Ключевые функции
- `load_snapshot`: чтение и проверка локального BIRD snapshot; возвращает список профилей без побочных эффектов.
- `candidate_links`: извлечение Reality VLESS URI; пропускает заглушки и неподдерживаемые транспорты.
- `atomic_write`: запись через временный файл и rename; сохраняет права доступа.

## Failure Modes
Некорректный или отсутствующий локальный snapshot оставляет последний список кандидатов. Обновление списка не означает переключение активного Telegram-подключения. Повторный отказ SOCKS вызывает selector; его fallback сохраняет последний активный Xray-конфиг. Актуализация самого зеркала должна быть отдельным безопасным producer, не имитирующим второе Happ-устройство.
